## Отменено и отложено

| Пункт | Статус | Обоснование |
|---|---|---|
| Docker + docker-compose | ❌ отменено | проект не деплоится; инфраструктура остальных проектов — systemd + `/opt`, контейнеры добавили бы второй путь обслуживания без выгоды. Само `.env` уже работает через `node --env-file-if-exists` |
| nginx + rewrite для SPA | ⏸ отложено | правило `try_files $uri $uri/ /index.html` нужно только при выкладке статикой. Рецепт сохранён ниже, чтобы не искать заново |
| Деплой на VPS / Netlify | ⏸ отложено | вне задачи портфолио |
| pg_trgm и GIN-индексы | ⏸ отложено | `ILIKE '%…%'` по 47 строкам — мгновенно; вернуться при тысячах записей |
| Миграции (отдельный инструмент) | ⏸ отложено | схема идемпотентна (`CREATE TABLE IF NOT EXISTS`, `ADD COLUMN IF NOT EXISTS`); для одного разработчика этого достаточно |

**Рецепт rewrite (если однажды понадобится):**

location /api/ { proxy_pass http://127.0.0.1:4000; }

## 🔜 Предлагается

### 1. Поиск в интерфейсе — 2 часа

API уже принимает `?q=` и ищет по названию и составу (проверено: `q=lime` → 16 записей),
но в UI поля нет — фича готова наполовину и не видна.

- поле в шапке каталога, ввод с debounce 300 мс;
- запрос через существующий `search({q})`, сброс рядом с полем;
- состояние «ничего не найдено» уже есть;
- тест: ввод → запрос с `q`, очистка → полный каталог.

**Готово, когда:** ввод «lime» в интерфейсе даёт 16 карточек, очистка возвращает 47.

### 2. Картинки коктейлей — 6–8 часов

Сейчас каталог — это список текста. Картинка меняет восприятие сильнее любой другой
доработки.

- `ALTER TABLE cocktails ADD COLUMN IF NOT EXISTS image_url text` (+ в `CREATE TABLE`);
- админка: поле ссылки, затем загрузка файла (drag&drop) → `POST /api/uploads`
  (проверка MIME и ≤2 МБ, файл в `backend/uploads/`, раздача через `express.static`);
- сжатие — **в браузере через canvas** (до 1200 px), чтобы не тащить нативный `sharp`;
- карточка: `<img loading="lazy" :alt="cocktail.name">` + заглушка, если пусто;
- импорт/экспорт: колонка `image_url` (старые файлы без неё читаются как NULL).

**Готово, когда:** загрузил фото → видно в каталоге → фото проходит экспорт и импорт.

### 3. Разложить 20 «Not categorized» — 30 минут (нужно твоё участие)

Без фильтра они недоступны, кроме отдельной кнопки «Not categorized». Половина из них
вообще не IBA-коктейли — распределять должен человек, а не скрипт.

- список 20 названий — в [AUDIT.md](AUDIT.md);
- после решения: правка через админку или SQL, сид перегенерируется из базы.

### 4. Доступность — 1–2 часа

- `<html lang="en">` при русском интерфейсе → `lang="ru"` (влияет на скринридеры и перевод браузера);
- `:focus-visible` для кнопок фильтров и админки (сейчас видна только подсветка темы);
- пропуск к контенту (`skip-link`) — пригодится, если появится меню;
- проверить контраст в теме `night` (сейчас не измерялся).

**Готово, когда:** страница проходит ручную проверку с клавиатуры (Tab → фильтры →
карточки → админка), и `lang` соответствует языку.

### 5. Инфраструктурные мелочи — 1 час

| Что | Зачем |
|---|---|
| `"engines": {"node": ">=20.19"}` в оба `package.json` | vite 8 требует Node ≥20.19; без поля падение на старом Node выглядит загадочно |
| `.nvmrc` с `22` | совпадает с версией в CI |
| `LICENSE` (MIT) | без лицензии код формально «все права защищены» |
| `frontend/README.md` | сейчас там шаблон Vite: «This template should help get you started» — заменить на ссылку на корневой README |
| `frontend/src/views/AboutView.vue` | заглушка «This is an about page», маршрут нигде не сслыться; либо наполнить, либо удалить вместе с TODO в `Header.vue` |

### 6. Мелкие улучшения по коду (по мере интереса)

- `GET /api/cocktails` (для админки) отдаёт до 500 записей без пагинации — при росте
  каталога админку стоит перевести на тот же `/search`;
- `random()` в Postgres делает полный проход — на 47 строках незаметно, при росте
  заменить на выбор по случайному смещению;
- счётчики фильтров считаются коррелированными подзапросами (9 фильтров × 47 строк);
  при росте — один агрегирующий запрос или материализованное представление.

## Как выбирать, что делать дальше

1. **Видимое для читателя GitHub** (картинки, поиск) — сначала: это портфолио.
2. **Гигиена репозитория** (engines, LICENSE, README фронтенда) — быстро и заметно тому,
   кто открыл код.
3. **Доступность** — показывает уровень зрелости, стоит дёшево.
4. **Производительность** — только когда появятся данные, оправдывающие оптимизацию.
