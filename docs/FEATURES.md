# Возможности приложения

Коротко: каталог коктейлей с фильтрами и случайным выбором, плюс закрытая админка,
через которую эти данные и ведутся.

---

## Публичная часть — каталог (`/`)

### Фильтры

Три типа, все живут в таблице `filters` и правятся из админки — в коде нет ни одного
захардкоженного фильтра:

| Тип | Как совпадает | Примеры из сида |
|---|---|---|
| `category` | точное равенство с `iba_category` | Classics, Unforgettables, New Era, Not categorized |
| `ingredient` | подстрока в составе (без учёта регистра) | gin, rum, tequila, sour → ищет `lime` |
| `volume` | `volume > threshold` (мл) | big volume → > 150 мл |

Подписи и значения задаются в админке, число совпадений (`count`) считается в SQL
и показывается в подсказке кнопки. Иконки есть у пяти «родных» фильтров; для новых
из админки рисуется текстовая кнопка.

Поведение: клик по фильтру перезапрашивает первую страницу; повторный клик по тому же
фильтру снимает его; «сбросить» возвращает весь каталог. Фильтры **не накапливаются** —
это было отдельным багом в первой версии (фильтровалось уже отфильтрованное).

### Поиск и пагинация

- страница по 25 коктейлей, кнопка «Показать ещё (N)» догружает следующую;
- счётчик «показано N из M» берётся из `total`, который считает Postgres;
- в API уже есть поиск по строке (`?q=` — по названию и составу), в интерфейсе поля
  пока нет: см. [ROADMAP.md](ROADMAP.md).

### Случайный коктейль

Кнопка `RANDOM` берёт случайный коктейль **на сервере** в рамках текущего фильтра
(`ORDER BY random()`), а не из загруженной страницы — иначе выбор всегда был бы
из первых 25.

### Состояния экрана

| Ситуация | Что видит пользователь |
|---|---|
| Идёт запрос | «Загружаю каталог…» |
| API недоступен | текст ошибки + кнопка «Повторить» |
| Каталог пуст | «Залейте данные через админку — вкладка Импорт» |
| Фильтр без совпадений | «Под фильтр «X» ничего не нашлось» + сброс |
| Кнопка «Показать ещё» | остаток + «страница N из M» |

### Оформление

Две темы — `day` и `night` — переключаются **автоматически по времени суток**
(`utils/themesSwitcher.js`: ночь с 16:00 до 9:00). Ручного переключателя нет.

## Админка (`/admin`)

Закрыта паролем. Пароль сравнивается на сервере (constant-time), взамен выдаётся
HMAC-токен на 12 часов, он хранится в `localStorage`. Пять неудачных попыток с одного
IP — блокировка на 15 минут (`429` + `Retry-After`).

### Вкладка «Напитки»

Таблица всех коктейлей: правка прямо в строке (название, состав, объём, цена,
категория), добавление новой записи, удаление с подтверждением.
Категории подставляются в datalist из фактических значений в базе — опечатку
вроде `Unforgetables` больше не создать случайно.

### Вкладка «Фильтры»

Список фильтров по типам, правка подписи/значения/порога/порядка, добавление и удаление.
Добавил ингредиент `vodka` — он сразу появляется на главной, без деплоя.

### Вкладка «Импорт / Экспорт»

**Импорт:** файл (CSV, TSV, JSON) → предпросмотр первых строк → режим → отчёт.

| Режим | Поведение |
|---|---|
| `merge` | валидные строки применяются, битые попадают в отчёт с номером строки; совпадение по `id`, а если его нет — по названию |
| `replace` | каталог заменяется целиком, но **файл проверяется до удаления**: одна битая строка — импорт отменяется, данные остаются |

Колонки: `id, name, composition, volume, price, iba_category`. `id` необязателен,
цена — одно или два числа (`14` или `14 20`).

**Экспорт:** вся база в CSV (с BOM — Excel не ломает кириллицу) или JSON. Формат CSV
тот же, что принимает импорт, поэтому «выгрузил → залил обратно» работает без правок.

## Чего сознательно нет

| Нет | Почему |
|---|---|
| Пользователей, регистрации, ролей | один админ; роли не нужны для задачи |
| Картинок коктейлей | не реализовано, стоит в плане |
| Поиска в интерфейсе | API готов, UI — в плане |
| Корзины, заказов, цен для гостей | это каталог, а не магазин |
| Деплоя, Docker, HTTPS | проект портфолийный, живёт только в GitHub |
| Мультиязычности | интерфейс русский, `lang` в HTML — см. аудит |

## Крайние случаи, которые проверены тестами

- вход: неверный пароль → `401`, шестая попытка → `429`;
- закрытые методы без токена → `401`;
- импорт `replace` с битой строкой → `400`, каталог не изменён;
- импорт `merge` с битой строкой → валидные применены, отчёт с номером строки;
- поиск с `%` или `_` в запросе не расширяет выборку (экранирование LIKE);
- `per_page=500` зажимается до 100, `page=0` — до 1;
- чужой `Origin` → `403`, разрешённый → заголовок CORS выставляется;
- ошибка базы → `500` с общим текстом, детали только в логе сервера.
